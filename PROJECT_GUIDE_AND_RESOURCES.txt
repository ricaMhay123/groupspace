1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
================================================================================
GroupSpace is an all-in-one collaborative workspace and team productivity
platform tailored for students, project teams, student organizations, and
creatives. It solves the friction of managing multiple tools by unifying:
  - Multi-workspace switching with 6-character invitation codes.
  - Role-based permissions (Workspace Leader vs Collaborator).
  - 4-column Kanban board featuring a Leader Dual-Approval workflow.
  - Collaborative rich-text Notebook with tag filters and search.
  - Expense Ledger with an automated debt-simplification settlement algorithm.
  - Isolated Personal Space for private notes, checklists, and budgets.
  - Workspace Discussion boards and real-time activity feed audit trail.

2. PROGRAMMING LANGUAGES & CORE WEB STANDARDS
================================================================================

1. JAVASCRIPT (ECMAScript 2024 / Full-Stack JS)
   - Definition: The high-level, dynamic programming language of the web.
   - Role in GroupSpace: JavaScript powers both the backend (via Node.js) and
     the frontend client, providing a unified language across the entire stack.
   - Usage:
     * Backend: API routing, business logic, password verification, SQL queries.
     * Frontend: Dynamic UI updates, modal controllers, state handling, async
       fetch requests.

2. HTML5 (HyperText Markup Language 5)
   - Definition: The standard markup language for creating structured web pages.
   - Role in GroupSpace: Defines semantic structures for all pages:
     * index.html: Landing page with interactive feature showcase.
     * login.html & register.html: Secure authentication portals.
     * workspaces.html: Workspace hub for creating and joining groups.
     * dashboard.html: Main single-page application (SPA) workspace interface.
     * about.html & contact.html: Information and contact channels.

3. CSS3 (Cascading Style Sheets 3)
   - Definition: The style sheet language used to format layout, design, and
     presentation of HTML elements.
   - Role in GroupSpace: Implements the "Nordic SaaS Minimalist" design system.
   - Key Features Used:
     * CSS Custom Properties (Variables): Reusable design tokens for colors,
       spacing, borders, elevation, and typography.
     * Fluid Typography: `clamp()` formulas ensuring text scales smoothly from
       smartphones (320px) to ultra-wide displays (4K).
     * CSS Grid & Flexbox: Responsive layouts for Kanban boards, expense
       summaries, sidebars, and dashboards.
     * Glassmorphism & Micro-animations: Blur backdrops, hover elevation,
       smooth badge transitions.

4. SQL (Structured Query Language / PostgreSQL Dialect)
   - Definition: The standard domain-specific language for managing and querying
     relational database management systems.
   - Role in GroupSpace: Schema definitions, relational joins, table indexes,
     cascading deletions, and secure parameterized queries.

3. BACKEND RUNTIME, FRAMEWORKS & LIBRARIES
================================================================================

1. NODE.JS (v18 - v24)
   - Definition: An open-source, cross-platform JavaScript runtime environment
     executing code outside web browsers on Google Chrome's V8 engine.
   - Why Used: High-throughput asynchronous I/O and non-blocking event loop,
     ideal for real-time collaboration.

2. EXPRESS.JS (v4.21+)
   - Definition: A minimalist, flexible Node.js web application framework.
   - Why Used: Provides powerful routing, JSON request body parsing, static
     file hosting, error handling, and middleware composition.

3. @NEONDATABASE/SERVERLESS
   - Definition: Official driver for querying Neon PostgreSQL over HTTP/WebSockets.
   - Why Used: Allows fast, serverless database connections without persistent
     connection pool exhaustion, perfect for cloud deployment platforms like Render.

4. BCRYPTJS
   - Definition: Optimized JavaScript implementation of the bcrypt password
     hashing function.
   - Why Used: Protects user credentials by generating salted, computationally
     expensive one-way cryptographic hashes.

5. JSONWEBTOKEN (JWT)
   - Definition: Compact, URL-safe means of representing claims between two parties.
   - Why Used: Generates signed authentication tokens containing user ID and
     email, verifying user identity on protected API endpoints.

6. COOKIE-PARSER
   - Definition: Express middleware that parses Cookie headers and populates
     `req.cookies`.
   - Why Used: Enables reading secure HTTP-only cookies containing auth tokens.

7. CORS (Cross-Origin Resource Sharing)
   - Definition: Middleware that enables secure communication across differing
     domains and ports.
   - Why Used: Configured to allow secure requests between client and server.

8. DOTENV
   - Definition: Zero-dependency module that loads environment variables from a
     `.env` file into `process.env`.
   - Why Used: Keeps sensitive credentials (database strings, JWT secrets,
     SMTP passwords) out of public source code.

9. NODEMAILER
   - Definition: Node.js module for sending emails via SMTP.
   - Why Used: Sends One-Time Password (OTP) verification codes to users during
     registration and password recovery.

4. DATABASE, STORAGE & CLOUD INFRASTRUCTURE
================================================================================

1. NEON SERVERLESS POSTGRESQL
   - Definition: Fully managed serverless PostgreSQL cloud database with
     automatic scaling, instant branching, and storage-compute separation.
   - Database Tables Created:
     * `users`: Account profile, hashed password, avatar initials, status.
     * `email_verifications`: OTP codes, expiration timestamps, email addresses.
     * `groups`: Workspace meta, join codes, categories, privacy, themes.
     * `group_members`: User membership roster and roles (LEADER, MEMBER).
     * `tasks`: Kanban tasks with priority, status, assignee, and approvals.
     * `task_comments`: Notes, feedback, and rejection comments on tasks.
     * `notes`: Collaborative notebook pages with tags and pinned status.
     * `expenses`: Logged workspace expenses with amounts and payees.
     * `expense_splits`: Granular participant cost distribution.
     * `discussions`: Forum discussion topics.
     * `discussion_comments`: Threaded replies to discussion topics.
     * `personal_items`: Private notes, private to-dos, and private expenses.
     * `activities`: Audit log recording timestamps, actions, and actors.

2. RENDER CLOUD HOSTING
   - Definition: Unified cloud application platform that builds and runs web apps
     directly from GitHub repositories.
   - Configuration:
     * Build Command: `npm install`

3. GITHUB REPOSITORY & CI/CD

5. SECURITY, AUTHENTICATION & CRYPTOGRAPHY
================================================================================

1. PASSWORD HASHING (Salt Rounds = 10)
   - Plaintext passwords are NEVER stored in the database. Every password undergoes
     bcrypt hashing with a unique cryptographic salt.

2. JSON WEB TOKEN (JWT) DUAL AUTHENTICATION
   - Supports both `Authorization: Bearer <token>` HTTP header and secure
     HTTP cookies.
   - Protected routes use `auth.middleware.js` to decode tokens and attach
     `req.user`.

3. ROLE-BASED ACCESS CONTROL (RBAC)
   - `role.middleware.js` checks group permissions before sensitive actions.
   - Workspace Leaders (`LEADER`) have exclusive permissions to:
     * Approve or reject Kanban tasks.
     * Edit workspace settings.
     * Change member roles.
   - Collaborators (`MEMBER`) can create tasks, mark them ready for review,
     take notes, log expenses, and participate in discussions.

4. PARAMETERIZED SQL QUERIES (SQL Injection Prevention)
   - Neon tagged template literals (`sql`...``) automatically parameterize inputs,
     preventing SQL injection vulnerabilities.

7. CORE APPLICATION MODULES & ALGORITHMS
================================================================================

1. KANBAN TASK BOARD & DUAL-APPROVAL WORKFLOW
   - 4 Columns:
     * 1. To Do (`TODO`)
     * 2. In Progress (`IN_PROGRESS`)
     * 3. Awaiting Approval (`PENDING_APPROVAL`)
     * 4. Approved Done (`DONE`)
   - Dual-Approval Logic:
     * When a team member finishes a task, they move it to `PENDING_APPROVAL`.
     * It cannot transition to `DONE` without explicit approval by a Workspace
       Leader.
     * Leaders can approve the task or send it back with revision feedback notes.

2. EXPENSE LEDGER & DEBT SIMPLIFICATION ALGORITHM
   - Tracks shared purchases and who participated in the split.
   - Smart Net Settlement:
     * Computes net balance for every member: `Net = Total Paid - Total Share`.
     * Separates members into Creditors (positive balance) and Debtors (negative balance).
     * Solves transactions iteratively with greedy matching to resolve debts
       with the minimum possible number of bilateral payments.

3. COLLABORATIVE NOTEBOOK
   - Shared searchable documentation for meeting minutes, project briefs, and notes.
   - Instant client-side live search and tag filtering.

4. ISOLATED PERSONAL SPACE
   - Completely private productivity environment.
   - Scoped strictly by `user_id` where `group_id IS NULL`.
   - Invisible to other workspace leaders or members.

How updates are pushed to the live website:
1. Edit code locally in your development workspace.
2. Stage all modifications:
   `git add .`

   `git commit -m "Your descriptive message"`

10. GLOSSARY OF KEY TERMS & DEFINITIONS
================================================================================

- API (Application Programming Interface): Set of rules and protocols allowing
  the frontend client to communicate with the backend server.
- ASYNCHRONOUS (Async/Await): Non-blocking programming model allowing tasks
  (like database queries or network calls) to execute in the background without
  freezing the application.
- BCRYPT: Cryptographic password-hashing function designed to protect stored
  passwords against brute-force attacks.
- CI/CD (Continuous Integration / Continuous Deployment): Automated process of
  testing and deploying code changes immediately upon committing to a repository.
- CLAMP() FUNCTION: CSS mathematical function taking three parameters
  (minimum, preferred, maximum), allowing properties like font sizes to scale
  fluently with screen viewport width.
- CORS (Cross-Origin Resource Sharing): Security mechanism in browsers restricting
  resources requested from another domain.
- CRUD (Create, Read, Update, Delete): The four basic operations performed on
  persistent database storage.
- DUAL-APPROVAL WORKFLOW: Quality assurance workflow where an assigned member
  submits a completed task for review, requiring a Workspace Leader's sign-off
  before marking it complete.
- ENDPOINT: Specific URL and HTTP method (GET, POST, PATCH, DELETE) exposed by
  a web server to perform actions or return data.
- ENVIRONMENT VARIABLES (.env): Secure configuration values stored outside
  code to keep secrets like database credentials safe.
- FLUID TYPOGRAPHY: Typography scaling technique that dynamically adjusts font
  sizes between minimum and maximum boundaries based on viewport width.
- GLASSMORPHISM: Modern UI design trend featuring semi-transparent surfaces with
  background blur (`backdrop-filter`) and subtle borders.
- JWT (JSON Web Token): Secure, digitally signed string used to authenticate
  users across stateless HTTP requests.
- KANBAN BOARD: Visual project management tool organizing tasks across workflow
  stages (To Do, In Progress, Review, Done).
- MIDDLEWARE: Software functions in Express.js executed in a pipeline between
  receiving a client request and sending the final response.
- MVC (Model-View-Controller): Architectural pattern separating application data
  (Models), business logic (Controllers/Services), and user interfaces (Views).
- NEON POSTGRESQL: Cloud database architecture providing serverless PostgreSQL
  instances with instant HTTP/WebSocket drivers.
- NODEMAILER: Node.js library for sending emails via SMTP protocols.
- OTP (One-Time Password): Short numeric code valid for a single session or
  transaction used for two-step verification.
- RBAC (Role-Based Access Control): Access security model assigning permissions
  based on user roles (Leader vs Member).
- RENDER: Cloud hosting platform providing scalable compute and hosting for web apps.
- REST (Representational State Transfer): Standard architectural style for
  designing networked web APIs using standard HTTP verbs.
- SPA (Single-Page Application): Web application interacting with the user by
  dynamically rewriting the current web page rather than loading entire new pages.
- SQL INJECTION: Security vulnerability where malicious SQL commands are injected
  into input fields. Prevented in GroupSpace via parameterized queries.
